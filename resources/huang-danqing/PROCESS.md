最终基线核对：**4,641＋442＋2,607＝7,690**，所有原始投稿均能对应到主目录、待分类清单或合并记录。

## 最终采用的规则

- 标题示例：“五六炮绝招9-2还是天天中刀复盘……”精简为“五六炮”；“五八炮之三子归边一局棋……”精简为“五八炮三子归边”。
- 先合并明显副本，以及同日/相邻日具体着法相同的实战、复盘版本；再精简展示标题，按北京时间日期和精简后标题做最后一轮去重。
- 同组保留较长版本，时长相同时选最新投稿。不同日期的同名棋题可以分别保留。
- 信息不足的投稿放入[待分类清单](pending.md)，不猜测标题，不将占位名称当作相同内容。
- Markdown、CSV、Excel、月份分表、索引和合并记录使用同一份结果。内容匹配基于公开元数据，未提取视频实际棋谱或逐帧比对。

详细匹配阈值和示例见[归并规则](METHOD.md)。

## 每日更新

Multica 定时唤醒信球之手，计划为**每天北京时间 09:00**，维护此仓库的 `main` 分支。

每次从最新投稿开始分页，回看至缓存最新发布时间之前至少七天，并遇到完整已知页面后停止；因此连续多天未运行时也会追赶新增投稿。以 BV 编号更新元数据缓存，再完整执行既定去重、精简、分类及导出流程。保留历史缓存，不因某一页访问失败或视频暂时不可见而删除历史资料。

```bash
python3 -B tools/update_huang_danqing.py
```

命令仅使用 Python 标准库；无需 B 站登录。原始公开元数据快照保存在 `data/huang-danqing.json.gz`，供重复匹配及重建使用；目录里的展示标题仍保持精简。

离线重建及校验：

```bash
python3 -B tools/update_huang_danqing.py --offline
```

更新先在临时目录运行，核对所有源记录有归属、合并记录指向有效链接、主目录同日无重复标题等条件，通过后才替换仓库文件。接口访问失败则报错并保留现有目录。有变化时由定时运行的代理提交、推送并回复仓库链接；无变化时不制造提交，使用定时检查签退记录结果。

定时规则由 Multica 保存，不依赖本地进程常驻。可在该任务的定时规则中停用；关闭、完成或取消该任务会停用它的定时唤醒，恢复任务不会自动恢复规则。
